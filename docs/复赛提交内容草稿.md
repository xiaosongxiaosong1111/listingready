## 业务价值与市场分析

### 目标用户与业务痛点

我们聚焦需要整理英文商品资料的中小跨境卖家和运营人员。原始资料可能分散在供应商说明、包装、照片和官网页面中。使用通用对话工具生成文案时，运营仍需判断哪些句子来自原始事实，哪些是模型根据商品类别补出的假设。

ListingReady 处理的是“事实整理到待发布资料包”的环节，不提供商品采购建议，不预测销量，不代替平台审核，也不自动向 Amazon 上架。我们首先解决资料缺失时仍被模型写成确定卖点的问题。

上述痛点是本项目的业务假设和产品切入点。目前尚未开展真实卖家访谈，不能宣称已经验证其普遍程度或形成付费需求。

### 应用场景与使用流程

运营选择商品品类并填写 13 项通用事实，为每项填写来源和确认状态。系统隔离待确认、已否定或仅由 AI 推断的内容，再通过比赛提供的模型生成英文标题、Item Highlights、卖点、描述及搜索词。

结果中的每段文案附事实引用。程序独立检查数字、单位、部分材质和功能声明、引用、宣传词与长度。运营可定位问题、修改文案并免费重检，也可补充事实后重新生成，对照新旧版本。

运营最终下载带原始事实、来源、确认状态、引用与风险报告的草稿。只有当前程序规则允许且人工主动确认复核，才允许准备人工复核包。复核包仍不是平台批准的发布内容。

图片为独立的参考图编辑实验流程，失败不清空文本；当前图像模型仍可能改变商品外观，必须逐图复核，不能把生成结果用作证明商品事实的实拍证据。

### 商业价值与预期效果

产品预期减少重复翻译、反复查找事实出处和修改后重新核对的操作，并让未知参数在发布前被明确暴露。这些是预期价值，不是已经测得的节省比例。

已测得的技术指标：2026 年 9 月 9 日凌晨，两个案例交替进行 10 次逻辑请求，最终结构化输出成功 10 次；共 13 次物理模型调用，其中 3 次风险修订，未出现格式失败重试。该结果来自旧版 `facts-only.v3.2026-09-08` 提示词，不能自动套用为后续版本的稳定性指标，也不是事实准确率、合规率或转化率。

建议在复赛后安排 3–5 名目标用户、每人 3 个已授权商品进行计时对照：记录从资料开始到人工可接受草稿的总时长、人工修订次数、无依据声明数量、补充事实次数和最终导出完成率。相同商品、相同事实资料及明确的审核标准是比较前提。没有对照数据前，不填写“节省 50%”“成本下降 40%”等数字。

### 市场前景与落地可行性

本阶段不使用未经核验的市场规模、增速或收入预测。可验证的落地路径是从单一市场的资料整理和审稿流程开始，先验证卖家能否独立完成一次上新资料准备，再考虑团队协作与多平台扩展。

商业模式为待验证假设：按商品资料包用量或团队订阅计费，是否愿意付费取决于实际节省的操作时间、风险检查价值和模型成本。尚未设置真实收费、签约卖家或商业客户。

规模化前需要补齐账户权限、配额与成本控制、数据保存策略、更全面的规则覆盖，以及比赛专属模型套餐能否用于面向评委或商业用户后端服务的适用确认。当前站点保留本人私有访问。

## 产品功能与使用说明

ListingReady 是一个多品类的英文商品资料工作台。它以有来源的事实为输入，使用 AI 生成草稿，再由独立规则与人工复核控制导出。桌面收纳盒只是资料缺失案例；厨房毛巾是官网资料案例。产品不自动识图确认参数、不自动上架，也不保证所有语义错误都能被程序发现。

核心功能：

1. 通用事实档案和来源确认，支持待确认、已确认、已否定与不适用。
2. 比赛 Token Plan 真实文案生成，每段携带事实引用。
3. 程序独立风险检查、问题定位、人工编辑与重检。
4. 补事实重生成与完整新旧对照。
5. 带风险报告的草稿和人工复核包准备、预览及保存。
6. 参考图编辑实验功能，结果单独人工复核，不冒充商品实拍。

体验路径：打开工作台 → 载入案例或填写商品 → 核对来源 → 生成英文草稿 → 检查风险与引用 → 补资料或改稿 → 准备导出文件 → 预览完整内容 → 保存 JSON。演示时应展示至少一次风险拦截，而非只展示成功结果。

本地运行与服务端环境变量方法见 README。密钥只在本地环境文件或托管 Secret 中配置，绝不写进参赛 PDF、视频或公开仓库。

## 技术架构及调用模型说明

系统由 React 工作台、Vinext 服务端 API 和 Cloudflare Worker 运行环境组成。浏览器把商品资料发送给服务端，服务端做输入校验、事实归一化，再向批准的比赛专属模型地址发起请求。模型结果经结构解析与独立规则检查后返回浏览器。导出时服务端重新检查，不能只相信浏览器传来的“通过”标记。

| 模块 | 当前实现 | 边界 |
| --- | --- | --- |
| 前端 | React、事实表单、编辑/对照、风险定位、素材复核、导出预览 | 当前会话刷新会丢失未保存状态 |
| 后端 | Vinext API、TypeScript、Cloudflare Worker | 本人私有测试，不是多租户正式服务 |
| 文案模型 | qwen3.6-flash，Token Plan 专属 chat/completions | 最多两次物理请求，不无限重试 |
| 图片模型 | qwen-image-2.0；另对 qwen-image-2.0-pro 做过验证 | 无自动图像保真鉴定，失败不自动重复计费 |
| 校验 | 确定性数字/单位/部分材质功能/引用/宣传词/长度规则 | 非全面语义审核或平台审批 |
| 数据 | 请求内处理、浏览器当前会话、用户下载 JSON | 无数据库、无向量库、无持久化商品库 |
| 编辑说明 | 从已确认事实生成的确定性编辑计划 | 非实时 AI 市场调研 |

正式 PDF 可用以下文字流程生成架构图：商品事实与来源 → 输入校验/隔离 → 比赛文本模型 → JSON 解析 → 独立风险检查 → 人工改稿/补事实 → 服务端复检 → 资料包。图片分支从已授权参考图和已确认外观资料进入比赛图像接口，输出经人工外观复核后才能附入复核包。
