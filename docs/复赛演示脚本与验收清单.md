# ListingReady 复赛演示脚本与验收清单

编写日期：2026-09-09。供录制 3–5 分钟复赛视频、现场演示和彩排使用；不是已录制的视频或已完成的验收。

## 演示要证明什么

面向准备 Amazon 美国站资料的中小跨境卖家，证明商品事实如何进入 AI 文案、缺失信息如何被隔离、风险如何定位和修订、结果如何经过人工复核再导出。不要把“能生成漂亮文案”当作唯一卖点。

建议以厨房毛巾为主案例、收纳盒为补充。主案例有明确资料，便于展示闭环；收纳盒展示资料不全时系统不会替卖家猜参数。工作台并未限制只能处理这两个品类。

## 录制前准备

- 使用已经验证的本地版本；录线上时先确认最新版本已部署。当前私有旧版不含全部本地能力。
- 隐藏邮件、终端环境变量、访问凭证和任何密钥。禁止打开 .env.local 录屏。
- 清理非演示窗口，字号至少清楚可读，关闭可能含隐私的通知。
- 核对演示案例与官网原始资料，不把品牌官网案例说成自有品牌商品、实际客户或品牌授权。
- 先做一次生成可用性检查。失败就采用明确标为“此前真实验收回放”的录制片段，不把预录内容说成实时返回。
- 保存至少一份可打开的 JSON 文件，检查其草稿/复核状态、事实、引用、风险报告和版本信息。不能只凭“已准备”提示判定已下载。
- 图片只有人工认为合格才能勾选；目前已有图片样本不合格，应展示局限，不用于包装成成功案例。

## 约 4 分钟讲解与操作

| 时间 | 操作画面 | 建议讲解 |
| --- | --- | --- |
| 0:00–0:25 | 工作台首屏及两种案例入口 | 我们是小宋1021队，项目叫 ListingReady，服务跨境卖家上新前的资料制作。它把有来源的商品事实转成可复核的英文草稿，不替用户猜参数，也不直接发布到平台。 |
| 0:25–0:55 | 厨房毛巾事实表，展开材质/尺寸/来源 | 同一项资料不仅有值，还记录来源和确认状态。待确认、已否定和只有 AI 推断的内容不会进入模型。这里公开官网案例仅用于展示流程。 |
| 0:55–1:30 | 生成请求、英文结果和事实引用 | 比赛提供的模型生成标题、商品亮点、卖点、描述和搜索词，每段提出事实引用。引用仍需人核对，系统不会把模型自评当成事实证明。生成等待可适当剪辑，并标注等待已缩短。 |
| 1:30–2:10 | 在描述中加入 waterproof → 重检 → 风险定位 | 为展示拦截，手动加入一条没有来源的防水声明。独立程序检查发现风险，定位到文案和需要核对的事实，并阻止人工复核包导出。此处是演示注入，不是模型原始输出。 |
| 2:10–2:40 | 删除错误声明，重检，查看改稿前后对照 | 修改后免费重检，保留改稿前后文案与引用变化。原资料改变时旧结果会失效，需要重新生成，防止沿用上一版参数。 |
| 2:40–3:15 | 准备草稿，预览 JSON；符合条件时人工确认后导出 | 导出不是截图：包内保留商品事实、引用、风险报告和生成记录，服务端重新检查导出条件。这里要真正保存并打开文件，不能只展示成功提示。 |
| 3:15–3:40 | 收纳盒案例的待确认项、图片实验标签 | 支持通用事实和多品类。照片能看到的形状不能证明材质、承重或销售包装数量。参考图编辑已接入，但外观保真仍在验证，不能当作商品实拍证据。 |
| 3:40–4:00 | 回到工作台，总结亮点和边界 | 我们的亮点是可追溯的事实输入、AI 生成后的独立检查、可解释的修订对照和受控导出。目前是可演示原型，下一步验证真实卖家的使用效果及图片保真。 |

建议保存两段原始录像：完整成功流程，以及风险注入与拦截。剪辑不得改变先后因果、隐藏风险提示或将人工修改伪装成模型生成。

## 补事实闭环备选片段

1. 载入厨房毛巾，保留官网资料，暂将材质和尺寸改为“待确认”。
2. 生成，核对结果没有宣称棉材质或具体尺寸；风险区显示资料待核对。
3. 对照官网，确认这两项；显示旧结果失效，不允许直接用旧结果复核导出。
4. 重新生成；核对新输出及前后对照。此流程已真实走通，但每次模型措辞和耗时可能不同。
5. 不预设每次必然零风险。若出现规则警告，解释并修订；保留实际结果。

## 主考官可能追问

**和直接用聊天机器人有什么不同？**  
区别在输入与审核流程，不在宣称模型更聪明：事实有来源和状态，生成按已确认资料约束；风险检查与生成模型分离；修改、前后版本和导出门槛集中在一个工作台。

**是否能保证没有幻觉？**  
不能。当前规则只覆盖数字、单位、部分材质功能、引用、宣传词及长度等常见问题。语义和图片仍须人工复核，风险为零不等于全面准确或平台审核通过。

**只能卖收纳盒吗？**  
不是。商品品类可填写，13 项事实结构覆盖多种非媒体类商品，厨房毛巾已做真实验证。不会因此宣称所有品类均已验收；高监管品类和类目特定政策未完整覆盖。

**为什么不自动上架？**  
本阶段聚焦上架前资料准备。平台账号、类目属性、权限、库存及发布风险需要单独接入和审核，当前没有实施自动发布。

**图片是不是已经成熟？**  
没有。已打通参考图编辑并加入外观复核门槛，但生成仍可能改变标签或视角。已保存失败样本，阶段成果不把接口成功等同于保真合格。

**省了多少时间？有多少客户？**  
目前没有真实卖家对照试验或客户数据，不能给出可靠百分比。拟用 3–5 名目标用户、每人 3 个商品，对比完整资料准备时间、修订次数和遗漏问题，并记录失败案例。

**数据与密钥安全吗？**  
模型密钥只在服务端环境中；不写入源码和导出包。商品资料按功能发送至比赛接口，参考图片需要授权。当前没有持久化商品数据库；这也意味着刷新后未导出内容会丢失。现阶段仅本人私有测试，不夸大为企业级安全认证。
