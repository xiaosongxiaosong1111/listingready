# ListingReady 核心闭环开发记录与交接

日期：2026-09-07。本文记录实际实现，优先于早期计划中的进度描述。参赛队伍：小宋1021队。

## 1. 本次范围

完成一个可使用的文本上新流程：多品类商品资料 → 明确事实来源与确认状态 → Token Plan 英文生成 → 独立规则检查 → 人工修改与重检 → 草稿 / 人工复核包导出。

这是复赛文本核心 MVP，尚非完整四模块成品。AI 场景图、图片识别、自动上架、账号、数据库、竞品抓取不属于本次完成项。前端支持一件商品一次生成；多品类不等于所有品类都有专门合规规则。

## 2. 已实现功能

| 功能 | 实际行为 | 主要代码 |

| 事实筛选 | 待确认、不适用、空值、缺少来源、仍含不确定措辞的事实不进入模型 | `lib/facts.ts` |

| 生成接口 | 专属 Token Plan 地址，服务端密钥，结构化输出 | `lib/generate.ts`, `app/api/generate-listing/route.ts` |
| 文案引用 | 每段 text + factIds，可展开查看及调整引用 | `lib/listing.ts`, `app/page.tsx` |
| 独立规则 | 数字、单位、部分材质和功能、宣传词、标题长度、引用、搜索词字节数 | `lib/validate.ts` |
| 自动修订 | 首次生成命中阻断规则时，将问题反馈给模型，至多再请求一次 | `lib/generate.ts` |

| 生成记录 | 模型、提示词版本、生成 ID、时间、耗时、请求次数、token 使用量 | `lib/domain.ts` |

## 3. 本次纠正的产品表述

1. 桌面收纳盒仅是案例，通用表单没有限定收纳盒属性。
2. 原页面“已识别照片”是静态描述。本版明确写“人工观察”，没有宣称已经接入多模态图片识别。
3. 原版 checks 由模型自报。本版风险报告由程序计算，不信任模型返回的通过结论。
4. “规则通过”不等于事实完全真实，也不等于 Amazon 审核通过。
5. 来源说明记录的是用户提供的出处；程序没有抓取、核验链接或鉴定供应商真实性。
6. 模型返回的 factIds 是待人工核对的引用关系，不能当作独立语义验证。
7. 上新包是资料包，不会自动创建 Amazon 商品，也不保证有品牌转售权限。

## 4. 商品数据契约

请求版本固定为 `schemaVersion: 1`，市场固定为 `marketplace: "amazon-us"`。

```json
{
  "schemaVersion": 1,
  "marketplace": "amazon-us",
  "category": "家居收纳",
  "facts": [
    {
      "key": "productName",
      "value": "窄型抽屉收纳盒",
      "status": "confirmed",
      "source": "seller",
      "sourceNote": "供应商规格书第 1 页，人工核对"
    },
    {
      "key": "features",
      "value": "抽拉取物，收纳文具和卡片",
      "status": "confirmed",
      "source": "photo",
      "sourceNote": "实物照片人工观察"
    }
  ],
  "keywords": "desk organizer",
  "bannedTerms": ["waterproof"]
}
```

未提供的其余事实会补成 pending，不会擅自填值。

13 个 key：`productName`, `brand`, `material`, `dimensions`, `color`, `packQuantity`, `structure`, `features`, `audience`, `useCases`, `care`, `weight`, `loadCapacity`。

状态：`confirmed`, `pending`, `not_applicable`。来源：`seller`, `packaging`, `supplier`, `photo`, `official`, `manual`。

生成最低要求：商品名称、核心功能均有可用的已确认内容和来源。复核导出还需要材质、尺寸、包装数量等核心资料完整，并解决全部警告和阻断项。本版核心字段要求是工作台策略，不是对 Amazon 所有类目的统一要求。

字符串不会静默截断；事实值上限 1200 字符、来源 600 字符、品类 80 字符、关键词 500 字符、禁用词 30 项且每项 80 字符。HTTP 请求体上限 32 KiB，包括分块请求的实际字节计数。

`keywords` 目前作为卖家备忘保存到导出，未传入生成模型，避免未经核实的关键词成为事实。禁用词作为负面约束传入。事实的来源说明和排除项的内容不发送给模型。

## 5. 输出契约与 API

`POST /api/generate-listing` 接受上述商品资料，返回 GenerationResult。每段文案是 `{"text":"…","factIds":["features"]}`；Listing 含 `title`, `itemHighlights`, `bullets[]`, `description`, `searchTerms`。

`POST /api/check-listing` 接受 `{"profile":ProductInput,"listing":Listing}`，返回 `{"report":RiskReport}`。允许手工改稿后重新检查，无需调用模型。

`POST /api/export-listing` 接受 `{"profile":ProductInput,"listing":Listing,"mode":"draft"|"reviewed","humanReviewed":boolean}`。服务端忽略客户端提供的 report，通过当前事实和文案重新检查。reviewed 不满足条件返回 409。draft 可导出，始终带草稿标识及风险报告。

| HTTP 状态 | 说明 |
|---|---|
| 400 | JSON、数据结构、必需事实不合格 |
| 403 | 浏览器 Origin 与本站不一致 |
| 409 | 复核包仍有待办、阻断或没有人工确认 |
| 413 | 请求体超过 32 KiB |
| 415 | 非 JSON 请求 |
| 429 | 上游套餐额度或频率受限 |
| 502 | 模型鉴权、服务、连接或输出问题 |
| 503 | 本地配置缺失或基地址不合要求 |
| 504 | 模型调用超时 |

响应包含 `Cache-Control: no-store`。错误响应不回传模型原始错误体、密钥或堆栈。

## 6. 提示词、重试与成本

默认模型：`qwen3.6-flash`；默认温度 0.2；输出 token 上限 3500。总模型等待预算 90 秒，浏览器 100 秒后停止等待。模型总调用数最多 2 次：首次有效结果有阻断时尝试一次修订；JSON 错误或上游 5xx 也可占用这次重试。第二次仍不合格时保留报告或返回结构错误，不无限重试。

401、403、429 以及网络异常不自动重试。超时或浏览器停止等待不保证上游取消计费。

首轮真实测试发现模型会给 searchTerms 空的 factIds，即使其他文案正确，也不能算引用完整。这促使本次加入独立检查后的有界修订；不能为了提高通过率直接删除引用规则。

## 7. 规则及资料来源（2026-09-07 核对）

- Amazon 官方新标题通知：[Updates to improve your product titles begin on July 27](https://sellercentral.amazon.com/seller-forums/discussions/t/145b6d0f-999c-4555-896c-c694bda2e470)。2026-07-27 起非媒体类标题上限 75 字符，Item Highlights 上限 125 字符。因此替换仓库旧版 200 字符规则。
- 搜索词采用 `<250` UTF-8 字节的保守设置：[Amazon Seller University Listing Guidance](https://m.media-amazon.com/images/G/28/AS/AGS/SU/CN_GS_Listing_Optimization_1.1_General_Guidance_EN.pdf)。该资料较早；上线真实类目前需再核对账户内当前规则。不得把“字符数”当作“字节数”。
- 厨房擦拭巾资料：[IKEA RINNIG 204.763.46](https://www.ikea.com/us/en/p/rinnig-dish-towel-white-dark-gray-patterned-20476346/)。记录棉材质、18 × 24 英寸、4 件装、图案、挂环及护理说明。未使用评论中的“速干、不掉毛、强吸水”等说法，也没把包装重量当成净重。
- 收纳盒事实：用户提供的 3 张真实照片；人工整理白色、抽屉、正面开口、文具收纳等可见特征，不推断材质和堆叠机制。

材质词典与功能规则仅覆盖部分常见表达；不能完整识别所有材质、同义词、复合句、否定、隐含性能和翻译错误。严格数值匹配可能对正确单位换算产生保守拦截，当前要求使用已确认的原始单位。医疗、环保、认证等声明按项目保守策略拦截，不声称每个词都是平台一概禁止。

## 8. 本地运行与密钥

推荐 Node.js 24 LTS。本项目原有最低版本 22.13，直接运行 TypeScript 单元测试要求当前 Node 的类型擦除支持；团队统一用 Node 24 可以避免版本差异。保留现有 Vinext / React / Cloudflare 架构和锁文件。

```bash
npm install
npm run dev
npm run typecheck
npm run test:unit
npm test
```

将 `.env.example` 复制为本地 `.env.local`，填写 `TOKEN_PLAN_API_KEY`。本机已有配置，不要覆写。基地址为 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，只有后端发送 Bearer Key。GitHub Secret 不会自动注入本地或 Sites，需要分别配置。

真实 API 验证是显式选择，会消耗比赛额度：

```powershell
$env:RUN_LIVE_TESTS='1'
npm run test:live
```

先启动本地服务。脚本针对两个案例检查 HTTP 生成、重检与两种导出；保存不含密钥的原始响应到已忽略的 `outputs/live-smoke-2026-09-07.json`。风险数量不强制为 0，否则会鼓励绕过风险规则；每一项都要人工解释。

## 10. 交给 CC 的后续重点

1. 先运行现有测试，确认当前版本，不要按旧单 SKU 表单重写。
2. AI 场景图：先核对比赛图像接口协议，不能假设图像模型也走 `/chat/completions`。图片应标 AI 生成，不能作为商品事实证据。保留商品形状、结构与颜色的验证路径。
3. 增强事实语义核验：独立模型复核或分句 claim 提取可作为补充；不得替换确定性数值和权限门禁。
4. 拓展通用属性与品类规则：单独记录规则版本、来源、适用市场、适用类目和更新时间。
5. 体验优化：重点减少填写负担、清晰指出待办，不要只加大面积营销介绍。
6. 公网评委体验：确认实际体验方式后再开放访问，并加入鉴权 / 全局限流 / 预算控制。现有同源检查不是用户身份验证，客户端按钮防重复也不是服务端限流。
7. 生成历史目前只在当前页面内存，刷新丢失；导出可保存本地。若增加持久化，需要另做存储、权限与隐私设计。
8. 导出中的生成元数据来自浏览器会话，没有服务端签名，不能作防篡改证据或计费凭据。
9. 准备复赛 PDF、视频与答辩：展示不完整事实如何触发待办、模型错误如何被拦住，以及第二品类如何走完流程。
